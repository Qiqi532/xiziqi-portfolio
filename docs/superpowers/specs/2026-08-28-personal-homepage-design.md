# 个人主页设计说明

**日期：** 2026-08-28  
**状态：** 已获用户确认，等待实施

## 1. 目标与定位

将现有摄影作品集演化为个人主页。主页以“在公式与光影之间，持续探索”为核心叙事，同时呈现物理学习、个人实践与摄影创作。

访客应在首页快速理解三件事：

1. 我是谁：中山大学物理学本科生，有研究、实践与影像创作三条并行的探索线。
2. 我正在做什么：光纤传感、天文光谱与机器学习相关学习/研究；校园传播、志愿与社会实践；摄影创作。
3. 在哪里继续了解：研究学习、个人实践、摄影和关于页提供更完整的内容。

## 2. 信息架构

### 顶部导航

- 主页
- 研究学习
- 个人实践
- 摄影
- 关于

### 首页（长卷叙事）

1. **首屏**：姓名、三重身份、主张句和一张克制的个人/环境照片。
2. **研究学习**：两项当前代表项目（光纤温盐传感、化学奇异星识别），入口通往研究学习页。
3. **个人实践**：校园传播/新媒体、志愿服务与社会实践的摘要，入口通往个人实践页。
4. **摄影精选**：风光、校园、人像三类精选，入口通往完整摄影作品集。
5. **个人切面**：少量旅行、会议或实践现场照片与简短文字，不做时间线或社交动态。
6. **联系**：稳定的公开邮箱和摄影合作入口。

### 专题页

- **研究学习页**：项目背景、个人贡献、代表论文、竞赛、技能。绩点、排名和完整课程分数不展示。
- **个人实践页**：宣传/新媒体工作、摄影传播、志愿服务和社会实践项目。以代表成果而非流水账呈现。
- **摄影页**：保留现有作品集、分类浏览和图片大图查看能力。
- **关于页**：简洁个人介绍、少量个人照片和联系入口。

## 3. 视觉与文案

- 中文为主，英文仅用于小型栏目标签（如 `RESEARCH & LEARNING`）。
- 采用“实验室冷灰”系统：近白为主背景、石墨色用于文字、雾灰用于分区，蓝灰仅用于标签、边线、链接和交互状态。
- 大图以低饱和或黑白方式呈现；摄影区域不使用大面积深色背景，内容卡片保持边界清晰、留白充足。
- 使用细线、轻量网格、编号和克制的几何圆形，形成实验记录和工程图纸般的秩序感，同时保持整体明亮。
- 字体风格为中文衬线标题配无衬线正文，体现理科生的克制与影像表达的温度。
- 首页主张句：**在公式与光影之间，持续探索。**

## 4. 内容来源与公开边界

- 科研、论文、竞赛和实践材料由 `intro/科研.pdf`、`intro/实习.pdf` 提炼。
- 个人切面照片从 `intro/pic/` 中筛选，实施时确认每张的构图、授权与公开意愿。
- 摄影作品继续使用现有风光、校园和人像图片集。
- 不公开电话、微信、出生年月、籍贯、成绩明细或排名。
- 删除留言板及其相关界面与数据请求；不新增新的后端或第三方服务。

## 5. 技术范围

- 基于现有 Vite + React + React Router + Framer Motion 项目渐进改造。
- 内容以本地静态数据模块维护；无需 CMS、动态后台、博客系统或外部数据接口。
- 延续 GitHub Pages 部署，并继续使用 `BASE_URL` 组织图片路径。
- 复用现有摄影图库、懒加载与大图查看组件；替换现有的单一摄影首页和关于页结构。

## 6. 组件与数据边界

| 单元 | 职责 | 依赖 |
|------|------|------|
| `Nav` | 五项导航与移动端入口 | 路由配置 |
| `Home` | 首页长卷模块编排与专题跳转 | 个人资料、项目、实践、摄影精选数据 |
| `Research` | 呈现项目、论文、竞赛和技能 | 研究数据 |
| `Practice` | 呈现实践经历与代表成果 | 实践数据 |
| `Portfolio` | 浏览摄影分类与图片大图 | 现有图片数据与图库组件 |
| `About` | 个人介绍、少量照片、联系入口 | 个人资料与照片数据 |

所有展示文案和卡片数据应置于 `src/data/` 的显式数据模块中；页面组件仅负责布局和交互，避免把长文案和重复数组分散在 JSX 内。

## 7. 交互、容错与可访问性

- 电脑端使用固定/半透明导航；移动端使用清晰的折叠菜单或轻量抽屉。
- 首屏照片若加载失败，保留纯色渐变背景与可读文案。
- 所有照片提供有意义的中文 `alt` 文本；仅作装饰的图片使用空 `alt`。
- 所有文字和链接保持足够对比度；卡片、导航和图库支持键盘聚焦。
- 继续保留摄影图片的懒加载与大图查看；关闭大图后焦点回到触发图片。
- 外部论文或平台链接应安全地在新标签打开，并有清晰链接文案。

## 8. 首版明确不包含

- 博客、新闻流、动态后台或内容管理系统。
- 留言板、评论、账号体系或新增数据库交互。
- 自动抓取社交平台内容、数据统计或任何分析追踪。
- 未经明确确认的私人联系方式、证书扫描件或全部获奖材料。

## 9. 验证标准

1. `npm run build` 成功。
2. 五个导航路由均能直接访问，且 GitHub Pages 的基路径正确。
3. 首页每个专题入口指向正确页面；摄影作品集、分类和大图查看仍可用。
4. 页面不存在留言板界面或对应 Supabase 请求。
5. 手机宽度与常见桌面宽度下导航、卡片、图片与文字不溢出。
6. 图片加载失败时，首屏和卡片仍保持可读；关键图片均具备替代文字。
7. 公开页面不包含已决定不展示的个人信息。
